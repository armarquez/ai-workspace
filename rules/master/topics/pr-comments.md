# Confirm before posting PR comments

Never post a comment on a pull/merge request — a new top-level comment or a reply within an existing review thread — without checking with the user first.

## Rules

- **Ask before posting, every time.** This applies even when the comment only confirms a fix for feedback the user already asked to be addressed — making the code change doesn't carry authorization to also post about it.
- **No exceptions for "obviously fine" comments.** A reply confirming a typo fix is still external, visible communication with other engineers — treat it the same as pushing code or opening a PR.
- **Applies regardless of platform** (GitHub, GitHub Enterprise, GitLab, etc.) and regardless of whether the comment is top-level or a threaded reply.

## Applies to

Any pull/merge request review interaction — replying to review comments, posting new PR comments, marking threads resolved.
